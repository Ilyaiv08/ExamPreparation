# Как добавлять учебный материал

Контент лежит в `content/**` типизированными данными — ни одного React-компонента.
Любая правка проверяется командой:

```bash
npm run typecheck && npm run content:check && npm test
```

---

## Как поправить описание дня плана

У каждого из 210 дней есть **два** текста:

| Текст | Где лежит | Можно ли менять |
|---|---|---|
| Дословный из программы | `content/curriculum/plan.generated.json` | Нет. Это разбор исходного файла программы: правится сам файл, затем `node scripts/parse-plan.mjs` |
| Человеческое объяснение | `content/curriculum/day-notes.ts` | Да, это текст платформы |

Формулировка программы написана телеграфно и для того, кто уже в теме:
«Flexbox: `display: flex`, `justify-content`, `align-items`». Новичку такая
строка ничего не объясняет. Поэтому платформа показывает своё объяснение
первым, а формулировку программы — рядом, под раскрывающимся блоком.
Подменять одно другим нельзя: студент должен видеть и то, что написано
в программе, и что это значит.

```ts
'day-03-1': {
  title: 'Раскладка в ряд: Flexbox',        // короткое имя, не список терминов
  theory:
    'Flexbox — способ расставить элементы в линию и управлять расстояниями ' +
    'между ними. Разбираемся, как прижать одно к левому краю, другое к правому.',
  practice: 'Собираем шапку сайта: логотип слева, меню справа.',
  why: 'Зачем это на экзамене — только там, где связь неочевидна.',
},
```

Правила, которые проверяются тестами:

- объяснение есть у **каждого** дня — пропуск роняет `npm run content:check`;
- в объяснении нет кода в обратных кавычках: если он остался, текст просто
  скопировали из программы вместо того, чтобы переписать;
- заголовок короче 60 символов;
- объяснение не совпадает дословно с текстом программы.

Объяснение показывается везде, где день попадается студенту: на дашборде
в карточке «Сегодня», в списке дней недели и на странице дня. Дословная
формулировка живёт только на странице дня, под раскрывающимся блоком.
Сценарный тест `4c` проверяет, что в списках не появилось обратных кавычек —
это верный признак, что где-то снова выводится текст программы.

## Как добавить тему

Темы лежат в `content/topics/month-NN.ts`.

### Шаг 1. Добавить объект темы

```ts
{
  id: 'css-container-queries',          // уникальный, латиницей через дефис
  title: 'Контейнерные запросы',
  tech: ['css'],
  monthNo: 1,
  weekNo: 3,
  importance: 'extra',                  // core | extra
  summary: 'Одно-два предложения: в чём суть и зачем это на экзамене.',
  mustKnow: ['Пункт 1', 'Пункт 2'],     // 3–5 пунктов
  theory: `## Заголовок

Текст в markdown: таблицы, списки, блоки кода.`,
  examples: [
    {
      title: 'Название примера',
      language: 'css',
      code: '.card { container-type: inline-size }',
      explanation: 'Почему именно так.',
    },
  ],
  mistakes: [
    { title: 'Что делают не так', why: 'К чему это приводит.' },
  ],
  quizId: 'quiz-css-container-queries', // тест создаётся отдельно
  taskIds: [],
  resources: [],
  examRefs: [],                         // идентификаторы требований экзамена
  prerequisites: ['css-responsive'],    // темы, которые должны быть пройдены
  estimatedMinutes: 30,
  planDays: ['day-03-4'],               // дни программы
  source: 'extra',                      // plan | exam | docs | author
}
```

### Шаг 2. Проверить

```bash
npm run content:check && npm run typecheck
```

Валидатор проверит: уникальность идентификатора, существование
`prerequisites`, `examRefs`, `planDays`, наличие теории и разбора ошибок.

### Что важно

- **`source` обязателен и должен быть честным.** `plan` — материал из учебной
  программы, `exam` — из задания демоэкзамена, `docs` — из документации
  технологии, `author` — добавлено разработчиком платформы. По этой метке
  студент понимает, откуда взялось требование.
- **`prerequisites` не должны образовывать цикл** — это проверяется тестом.
- **Новая тема без теста даст предупреждение**, но не ошибку: тест можно
  добавить следующим шагом.

## Как добавить практическое задание

Задания лежат в `content/tasks/`:

| Файл | Что внутри |
|---|---|
| `month-NN.ts`, `month-NN-css.ts`, `month-NN-js.ts` и подобные | Задания месяца по темам |
| `month-NN-daily.ts` | Задания для дней месяца, у которых практики не было |
| `week-assembly-mN.ts` | Сборки седьмых дней: задание на всё, что было за неделю |
| `week-assembly.ts` | Собирает сборки всех месяцев в один список |

Новое задание добавляют в тот файл, к которому оно ближе по смыслу, и
подключают в `content/tasks/index.ts`.

### Шаг 1. Выбрать среду выполнения

| Среда | Когда использовать |
|---|---|
| `js` | Функции, алгоритмы, обработка данных |
| `ts` | Когда проверяется именно типизация |
| `dom` | Разметка, стили, работа с DOM |
| `react` | Компоненты |
| `sql` | Схемы и запросы |

### Шаг 2. Написать задание

```ts
{
  id: 'task-css-container',
  title: 'Карточка, реагирующая на ширину контейнера',
  kind: 'function',       // function | fix-bug | find-bug | complete | output | api | db | files | app
  runtime: 'dom',
  difficulty: 3,          // 1…5
  tech: ['css'],
  topicIds: ['css-container-queries'],
  monthNo: 1,
  weekNo: 3,
  statement: `Условие в markdown. Требования — списком, без недосказанностей.`,
  requirements: ['Требование 1', 'Требование 2'],
  starterCode: `<style>\n  /* ваш код */\n</style>`,
  viewport: { width: 390, height: 844 },   // для заданий на адаптив
  tests: [ /* см. шаг 3 */ ],
  hints: [
    { level: 1, text: 'Направление мысли.', penaltyPercent: 10 },
    { level: 2, text: 'Часть алгоритма.', penaltyPercent: 25 },
    { level: 3, text: 'Почти готовая структура.', penaltyPercent: 40 },
  ],
  solution: `Полный код решения.`,
  solutionExplanation: `Разбор: почему так, а не иначе, и где обычно ошибаются.`,
  maxScore: 12,           // ОБЯЗАТЕЛЬНО равен сумме points всех тестов
  estimatedMinutes: 20,
  examRefs: ['m2-mobile'],
  planDays: ['day-03-4'],
  source: 'extra',
}
```

### Шаг 3. Написать тесты

Тесты — настоящие проверки исполнения. Доступные типы:

```ts
// Вызов функции с аргументами
{ id: 't1', name: 'Понятное название', type: 'call',
  entry: 'checkLogin', args: ['ivanov26'], expected: true, points: 3 }

// Вычисление выражения в области видимости решения
{ id: 't2', name: '…', type: 'expr', expression: 'items.length', expected: 4 }

// Произвольная проверка: ctx.get, ctx.assert, ctx.source
{ id: 't3', name: '…', type: 'assert', code: `
const result = ctx.get('validate')({ login: '' });
ctx.assert(Boolean(result.login), 'Пустой логин должен попасть в ошибки');
`, points: 4 }

// Проверка отрисованного документа: ctx.$, ctx.$$, ctx.css, ctx.text, ctx.wait
{ id: 't4', name: '…', type: 'dom', code: `
ctx.assert(ctx.$('header'), 'Нужен тег header');
`, points: 2 }

// Проверка React-компонента: ctx.render, ctx.click, ctx.change, ctx.submit, ctx.wait
{ id: 't5', name: '…', type: 'react', code: `
return ctx.render('Menu', { user: null }).then(() => {
  ctx.assert(ctx.$('[data-testid="login"]'), 'Гость должен видеть вход');
});
`, points: 4 }

// SQL: контрольный запрос и ожидаемая таблица
{ id: 't6', name: '…', type: 'sql-query',
  check: 'SELECT title FROM statuses ORDER BY id',
  expectedColumns: ['title'],
  expectedRows: [['Новая'], ['Мероприятие назначено']],
  ordered: true, points: 5 }

// SQL: структура таблицы и внешние ключи
{ id: 't7', name: '…', type: 'sql-schema', table: 'applications',
  columns: [{ name: 'id', pk: true }, { name: 'user_id', notNull: true }],
  foreignKeys: [{ column: 'user_id', refTable: 'users' }], points: 4 }
```

Тест можно пометить `hidden: true` — тогда студент увидит его название и
результат, но не ожидаемое значение.

### Шаг 4. Привязать к дню плана

Поле `planDays` связывает задание с днями учебного плана:

```ts
planDays: ['day-03-2'],
```

**У каждого из 210 дней должно быть хотя бы одно задание** — это проверяет
`npm run content:check` и модульные тесты. Правило не формальное: день без
практики превращается в чтение, а платформа существует ради того, чтобы
студент писал код каждый день.

### Шаг 5. Проверить

```bash
npm run content:check && npm run typecheck && npm test
npm run test:solutions      # прогон эталонного решения через песочницу
```

Последняя команда — главная. Она берёт `solution` каждого задания, вставляет
в редактор и прогоняет все его проверки по-настоящему. Без неё задание
с опечаткой в тесте выглядит целым ровно до того момента, когда студент
потратит на него полчаса.

### Правила, которые стоит соблюдать

- **`maxScore` = сумма `points` всех тестов.** Иначе прогресс будет врать —
  это проверяется и валидатором, и тестами.
- **`solution` — полный работающий код, а не фрагмент.** Студент открывает
  разбор, чтобы вставить его и запустить; кроме того, по нему работает
  `npm run test:solutions`. Для `dom`-задания это весь документ вместе
  с разметкой, для `js` — все объявления, включая данные из заготовки.
- **Три уровня подсказок**, штраф растёт с уровнем.
- **`solutionExplanation` объясняет «почему», а не пересказывает код.**
  Это главная обучающая часть задания.
- **SQL-заданию нужен `setupSql`**, кроме заданий вида «спроектируйте схему».

### Ловушка: проверки одного задания идут по одному документу

Все проверки задания выполняются подряд **без пересоздания** страницы или
React-компонента. Состояние переезжает из проверки в проверку: если первая
кликнула по кнопке, вторая увидит уже переключённое состояние, а `useState`
сохранит значение из предыдущего `ctx.render`.

Поэтому проверки пишут так, чтобы они не зависели от порядка:

```ts
// Плохо: рассчитывает на нетронутый компонент
ctx.click('#next');
ctx.assert(activeIndex() === 1, '…');

// Хорошо: сравнивает с тем, что есть сейчас
const before = activeIndex();
ctx.click('#next');
ctx.assert(activeIndex() === (before + 1) % 4, '…');
```

Второй приём — привести состояние к известному прямо в проверке:

```ts
if (ctx.css(ctx.$('#filters'), 'display') !== 'none') ctx.click('#toggle');
```

### Ловушка: анимации в фоновой вкладке

Браузер притормаживает CSS-анимации, когда вкладка не на виду, поэтому
проверка «подождать 700 мс и посмотреть на `opacity`» проходит не всегда.
Проверяйте объявление, а не проигрывание: `animation-name`,
`animation-duration`, `animation-fill-mode`.

## Как добавить теоретический тест

Тесты лежат в `content/quizzes/month-NN.ts`.

```ts
{
  id: 'quiz-css-container-queries',
  title: 'Контейнерные запросы',
  topicIds: ['css-container-queries'],
  tech: ['css'],
  monthNo: 1,
  difficulty: 2,
  passPercent: 70,        // 80 для тем с дословными требованиями экзамена
  examRefs: ['m2-mobile'],
  questions: [
    {
      id: 'q1',
      type: 'single',
      text: 'Вопрос?',
      options: [
        { id: 'a', text: 'Вариант' },
        { id: 'b', text: 'Другой' },
      ],
      correct: 'b',
      explanation: 'Почему верен этот вариант и чем плохи остальные.',
    },
    { id: 'q2', type: 'boolean', text: 'Утверждение.', correct: true, explanation: '…' },
    { id: 'q3', type: 'multiple', text: '…', options: [/* … */], correct: ['a', 'c'], explanation: '…' },
    { id: 'q4', type: 'match', text: '…', left: [/* … */], right: [/* … */],
      correct: { l1: 'r1', l2: 'r2' }, explanation: '…' },
    { id: 'q5', type: 'order', text: '…', items: [/* … */],
      correct: ['i1', 'i2', 'i3'], explanation: '…' },
    { id: 'q6', type: 'text', text: '…', correct: ['break'],
      caseSensitive: false, explanation: '…' },
  ],
}
```

### Правила

- **Пояснение обязательно у каждого вопроса.** Тест без пояснений не учит —
  это проверяется тестами.
- **`caseSensitive: true`** — только для значений, которые на экзамене
  проверяют дословно (`Admin26`, `Demo20`). По умолчанию сравнение мягкое:
  без учёта регистра, пробелов и пунктуации, «ё» = «е».
- **Правильный ответ должен быть из списка вариантов** — проверяется валидатором.
- **Эталонные ответы прогоняются тестом** и обязаны дать 100 %.

## Как добавить мини-проект

Проекты лежат в [`content/projects/projects.ts`](../content/projects/projects.ts).

```ts
{
  id: 'project-08-something',
  title: 'Название',
  goal: 'Одно предложение: что студент научится делать.',
  monthNo: 3,
  difficulty: 4,          // не ниже, чем у проекта предыдущего месяца
  tech: ['react'],
  topicIds: ['react-state'],
  examRefs: ['m2-cabinet-ux'],
  brief: `## Что делаем\n\nТехническое задание в markdown.`,
  requirements: ['Требование 1', 'Требование 2'],
  constraints: ['Без внешних библиотек'],
  checklist: [
    { id: 'c1', text: 'Пункт', weight: 3, verification: 'auto' },
    { id: 'c2', text: 'Пункт для самопроверки', weight: 2, verification: 'manual' },
  ],
  hints: [ /* три уровня */ ],
  resources: [],
  autoCheck: {            // необязательно
    runtime: 'react',
    maxScore: 20,         // = сумма points тестов
    starterCode: '…',
    tests: [ /* как у заданий */ ],
  },
  estimatedHours: 4,
  planDays: ['day-12-6'],
  source: 'author',
}
```

### Правила

- **Сложность не должна падать** от месяца к месяцу — это проверяется тестом.
- **В чек-листе обязан быть хотя бы один ручной пункт.** Проект без ручной
  части означал бы, что платформа проверяет всё сама — а это неправда.
- **`autoCheck` необязателен.** Для проектов вроде «прогон модуля 1 за
  90 минут» автопроверки нет вовсе, и честнее так и сказать.

## Как добавить экзаменационный вариант

### Официальный вариант

[`content/exams/demo.ts`](../content/exams/demo.ts) содержит вариант № 2
демоэкзамена 2026 года. **Его тексты — дословные цитаты из PDF.** Менять их
нельзя: на этом держится ценность режима. Если появится новый официальный
вариант, добавляйте его туда же с `kind: 'demo'` и `source: 'exam'`.

### Тренировочный вариант

Добавляется в [`content/exams/practice.ts`](../content/exams/practice.ts):

```ts
{
  id: 'exam-practice-delivery',
  title: 'Тренировочный вариант — «Доставка еды»',
  kind: 'practice',
  level: 'exam',
  domain: 'Служба доставки',
  source: 'author',                       // обязательно author
  sourceNote: 'Вариант составлен разработчиком платформы. Официальное задание — только вариант № 2.',
  description: `Чем этот вариант отличается и на что смотреть.`,
  totalMinutes: 240,                      // = сумма minutes модулей
  examRefs: ['m1-db', 'm1-register'],
  modules: [
    {
      id: 'practice-delivery-m1',
      moduleNo: 1,
      title: 'Проектирование и разработка',
      minutes: 90,
      instruction: `**Задание составлено разработчиком платформы.**\n\n…`,
      tasks: [
        { id: '…', kind: 'code', taskId: 'task-sql-schema', points: 8, title: '…' },
        {
          id: '…',
          kind: 'checklist',
          title: 'Чек-лист модуля 1',
          description: 'Эти пункты проверяются в вашем проекте.',
          points: 20,                     // = сумма points пунктов
          items: [{ id: 'c1', text: 'Пункт', points: 2 }],
        },
      ],
    },
    /* модули 2 и 3 */
  ],
}
```

### Обязательные правила

- **`source: 'author'` и честный `sourceNote`.** Тренировочный вариант нельзя
  выдавать за официальный — это прямое требование раздела 46 ТЗ, и оно
  проверяется тестом.
- **Три модуля, 90 + 90 + 60 минут**, сумма — 240.
- **В каждом модуле и автопроверяемые задания, и чек-лист.**
- **`points` чек-листа = сумма `points` его пунктов.**
- **Не копируйте дословные формулировки официального задания** в инструкции
  тренировочного варианта. Цитаты уместны только в пунктах чек-листа, где
  прямо отмечено, что это требование настоящего экзамена.
